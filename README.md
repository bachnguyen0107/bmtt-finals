# Topic 4 - Basic Keylogger: Detection, Execution & Defense

This repository contains the final demonstration code for Topic 4 of the
Introduction to Information Security course (Group G11, Ton Duc Thang
University). It accompanies our theory report and turns that theory into a
working attack-and-defense demonstration, carried out in an isolated
environment using only self-generated test data.

The project is built around three small Python programs. `keylogger.py` is the
attack: it installs a global low-level Windows keyboard hook (the
WH_KEYBOARD_LL mechanism) and appends every keystroke, with a timestamp, to a
local file named `keylog.txt`. `log_viewer.py` is a verification helper that
reads that log file and prints a clean summary of what was captured, so the
confidentiality breach is easy to show during the demonstration.
`secure_keyboard.py` is the defense: a mouse-driven on-screen keyboard whose
input is never seen by the keylogger, because clicking its buttons produces
mouse events rather than physical key presses.

## Setup

To run the demonstration you need Python 3.10 or newer and the `pynput`
library, which you can install with `pip install pynput`. The `tkinter`
library used by the on-screen keyboard ships with standard Python on Windows,
so there is nothing extra to install for it. Run everything inside an isolated
virtual machine, using test data you type yourself.

## Running the demonstration

Part A - the attack works:

1. Run the keylogger: `python keylogger.py`
2. Leave it running. Open Notepad and type some fake test text, for example
   `testuser  Passw0rd123`.
3. Press ESC to stop the keylogger.
4. Run `python log_viewer.py` (or open `keylog.txt`). Your typed text is
   there - confidentiality is broken.

Part B - the defense beats it:

1. Delete or rename `keylog.txt` so you start clean.
2. Run the keylogger again: `python keylogger.py`
3. Without touching the physical keyboard, run the on-screen keyboard:
   `python secure_keyboard.py`
4. Using only the mouse, click out `Passw0rd123` on the on-screen keyboard.
5. Press ESC to stop the keylogger, then run `log_viewer.py` again - the
   mouse-typed text is not there. The hook never fired.

## Why the defense works

`keylogger.py` installs a global keyboard hook, which only ever sees events
generated by physical key presses. Clicking buttons on `secure_keyboard.py`
is a mouse event that writes a character straight into a text field, so no
keyboard event is ever generated and there is nothing for the hook to capture.

## Limitations

The on-screen keyboard defeats a basic keyboard-hook keylogger only. It does
not stop screenshot spyware, mouse-coordinate loggers, clipboard monitors, or
accessibility/UI-automation capture. Real defense needs defense-in-depth: EDR,
application allowlisting, least privilege, and MFA.

## Authorized use

This code is for authorized laboratory use only. It should be run inside an
isolated virtual machine with test data you generate yourself, and never used
to capture anyone else's input. It deliberately has no network, stealth, or
persistence features, so it serves as a teaching artifact rather than real
malware.
